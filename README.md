# volzz

音量キーの長押しで曲を送る／戻す常駐アプリ。短押しは今までどおりの音量操作のまま。

- **音量アップを長押し** → 次の曲
- **音量ダウンを長押し** → 前の曲
- **短押し** → 通常の音量操作（変更なし）

対応: Android 9 (API 28) 〜 Android 16 (API 36)
成果物: `volzz.apk`（32 KB）

## 要求する権限: なし

`AndroidManifest.xml` に `<uses-permission>` は一行もない。インターネットも通知も
ストレージも使わない。APK を検査しても権限は出てこない。

```
$ aapt2 dump permissions volzz.apk
package: com.volzz
```

必要なのは**アクセシビリティ設定での有効化**だけ。そのサービスも最小限に絞ってある。

| 設定 | 値 | 意味 |
|---|---|---|
| `accessibilityEventTypes` | 指定なし (0) | 画面上のイベントを一切受け取らない |
| `canRetrieveWindowContent` | `false` | 画面の内容を読まない |
| `accessibilityFlags` | `flagRequestFilterKeyEvents` | キーイベントの横取りだけを要求 |

`onKeyEvent()` は音量キー以外を見た瞬間に `false` を返して手を引く。

## なぜアクセシビリティサービスなのか

アプリが自分の画面の外で物理キーを受け取る方法は Android にはこれしかない。
代わりの手段は `MediaSession` に `VolumeProvider` を付けて音量キーを丸ごと奪う
方法だが、それをすると本来の音量操作そのものが壊れる。今回の要件（短押しは
そのまま）とは両立しない。

アクセシビリティサービスはシステムが束縛して常駐させるので、常駐のための
フォアグラウンドサービスも通知も自動起動の権限も要らない。端末を再起動しても
システムが自動で繋ぎ直す。

## インストール

1. `volzz.apk` を端末に転送して開く（または `adb install volzz.apk`）
2. **Android 13 以降はここで一手間要る。** ストア以外から入れたアプリは
   アクセシビリティの項目が灰色で押せない（「制限付き設定」）。
   設定 → アプリ → volzz → 右上の **⋮** → **制限付き設定を許可** を押してから進む。
3. volzz を開いて「アクセシビリティ設定を開く」→ インストール済みアプリ →
   volzz → オン
4. 音楽を再生して、音量アップを長押しする

## 設定画面でできること

- **volzz を有効にする** — オフにすると音量キーに一切介入しない
- **長押しと判定する時間** — 250〜1000 ミリ秒をスライダーで調整（初期値 450）。
  短くすると曲送りが速くなるが、少し長めの音量操作が誤って曲送りになりやすい
- **再生中だけ介入する**（初期値オン）— 音が鳴っていないときは音量キーを完全に
  素通しする。普段の音量操作に痕跡を残さないための既定値
- **上下を入れ替える** — 長押しの向きを逆にする
- **短押しの扱い** — 下記の 2 モード
- **動作確認** — 受け取ったキーイベントの回数と直前の動作を表示

## 短押しの扱い（2 モード）

短押しと長押しは「離すまで分からない」ので、どちらかを選ぶことになる。
**どちらを選んでも、曲送りしたあとはキーを離すまで音量は動かない。**

### モードA「遅延なし」（初期値）

キー押下を横取りしたうえで、その場で音量を動かす。反応の遅れはない。
長押しが成立した時点で、その 1 段を押す直前の値に戻してから曲を送る。

- 音量操作に遅延がない
- 曲送りのとき音量が一瞬だけ動いて戻る

### モードB「音量を動かさない」

キーをいったん預かり、判定時間が過ぎたら曲送り、その前に離されたら
そこで初めて音量を動かす。

- 曲送りのとき音量が一瞬も動かない
- 音量操作が判定時間のぶん（初期値 450ms）遅れる

### なぜ押下を「通さず」に自分で音量を動かすのか

v1 では短押しを完全に端末任せにするため、最初の押下をシステムに通していた。
これが原因で、**曲送りのあともキーを離すまで音量が上がり続けた**。

押下を通すと、以降の自動リピートはシステム側（`InputDispatcher`）が生成する
ようになり、そのリピートはアクセシビリティのフィルタを通らない。つまり
volzz からは見えず、握り潰せない。押下を横取りしてしまえばリピートは
そもそも発生しないので、離すまで音量は一切動かない。

## 実機で確かめること

v1 の実機確認で、**キーイベントが volzz に届くこと**（`accessibilityEventTypes`
を指定しなくても `onKeyEvent()` が呼ばれること）は確認できた。

v2 では次を見てほしい。

1. **短押し** — 音量が遅れなく動くか。音量パネルが出るか
2. **長押し** — 曲が送られるか。動いた 1 段が戻るか
3. **長押しのあと、離すまで** — 音量が動かないこと（v2 の修正点）
4. **画面の上下** — 切れずに全部読めるか（v2 の修正点）
5. **画面消灯中** — ポケットの中で効くか。ここは端末差が出る可能性が高い。
   画面が消えているとき、システムは音量キーを早い段階で処理してしまうため、
   曲送りは効いても音量が一瞬動くことがある

### キーが届かないとき（他の端末で使う場合）

`accessibilityEventTypes` を指定していない（画面のイベントを一切受け取らない）
のが理由である可能性がある。その場合は
`app/src/main/java/com/volzz/VolzzService.java` の `onServiceConnected()` で

```java
info.eventTypes = 0;
```

を

```java
info.eventTypes = AccessibilityEvent.TYPE_WINDOW_STATE_CHANGED;
```

に変えて再ビルドすれば直る。privacy の観点では「前面のアプリ名が分かる」分だけ
情報が増えるので、必要になってから変える。

## ビルド

```sh
./gradlew assembleRelease
# → app/build/outputs/apk/release/app-release.apk を volzz.apk にコピーして配る
```

- JDK 17、Android SDK（platform 36 / build-tools 36.0.0）
- 依存ライブラリなし（AndroidX も使わない）。だから APK が 32 KB で済んでいる
- 署名鍵は `keystore/volzz.jks`（パスワードは `keystore.properties`、有効期間 30 年）。
  **この鍵は捨てないこと。** 失うと同じアプリとして更新できなくなり、
  入れ直しが必要になる

## 構成

```
app/src/main/
  java/com/volzz/
    VolzzService.java   音量キーの横取りと長押し判定
    MainActivity.java   設定画面と動作確認
    Prefs.java          設定の保存と診断情報
  res/xml/accessibility_service_config.xml   サービスの権限を最小に絞る宣言
  AndroidManifest.xml
```
