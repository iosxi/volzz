# volzz

音量キーの長押しで曲を送る／戻す常駐アプリ。短押しは今までどおりの音量操作のまま。

- **音量アップを長押し** → 次の曲
- **音量ダウンを長押し** → 前の曲
- **短押し** → 通常の音量操作（変更なし）
- **画面が消えていても効く**（v4 から。仕組みは別で、[下](#画面が消えているとき)に書いた）
- **曲が送れたら短く振動**（v7 から。次の曲は 1 回、前の曲は 2 回。設定で切れる）

対応: Android 9 (API 28) 〜 Android 16 (API 36)
成果物: `volzz.apk`（42 KB）

## 要求する権限: 振動だけ

```
$ aapt2 dump permissions volzz.apk
package: com.volzz
uses-permission: name='android.permission.VIBRATE'
```

`VIBRATE` は曲送りの合図に使う（v7 から）。保護レベルは normal で、インストール時に
自動で付き、許可を尋ねるダイアログも出ない。できることは振動だけで、そこから
何かを読み取ることはできない。設定の「曲送りのときに振動する」をオフにすれば
一度も使わない。**振動が要らないなら、この一行を消して再ビルドすれば権限ゼロに戻る**
（`AndroidManifest.xml` の `<uses-permission>` と `Media.buzz()` の呼び出し）。

これ以外は何も要求しない。インターネットも通知も位置情報もストレージも使わない。
必要なのは**アクセシビリティ設定での有効化**だけ。そのサービスも最小限に絞ってある。

| 設定 | 値 | 意味 |
|---|---|---|
| `accessibilityEventTypes` | 指定なし (0) | 画面上のイベントを一切受け取らない |
| `canRetrieveWindowContent` | `false` | 画面の内容を読まない |
| `accessibilityFlags` | `flagRequestFilterKeyEvents` | キーイベントの横取りだけを要求 |

`onKeyEvent()` は音量キー以外を見た瞬間に `false` を返して手を引く。

## なぜアクセシビリティサービスなのか

画面が点いているあいだ、アプリが自分の画面の外で物理キーを受け取る方法は
Android にはこれしかない。代わりの手段は `MediaSession` に `VolumeProvider` を
付けて音量キーを丸ごと奪う方法だが、それを常時やると音量パネルの見え方まで
こちらのセッションのものに変わり、本来の音量操作が壊れる。

そこで volzz は使い分ける。**画面が点いている間はアクセシビリティ**、
**消えている間だけ `VolumeProvider`**（消えている間はアクセシビリティに
キーが届かないため。[画面が消えているとき](#画面が消えているとき)）。
消えている間はパネルも出ないので、奪っても見え方は変わらない。

アクセシビリティサービスはシステムが束縛して常駐させるので、常駐のための
フォアグラウンドサービスも通知も自動起動の権限も要らない。端末を再起動しても
システムが自動で繋ぎ直す。

## インストール

1. `volzz.apk` を端末に転送して開く（または `adb install volzz.apk`）
2. **Android 13 以降はここで一手間要る。** ストア以外から入れたアプリは
   アクセシビリティの項目が灰色で押せない（「制限付き設定」）。
   設定 → アプリ → volzz → 右上の **⋮** → **制限付き設定を許可** を押してから進む。
3. volzz を開いて「アクセシビリティ設定を開く」→ インストール済みアプリ →
   volzz → オン
4. 音楽を再生して、音量アップを長押しする

## 設定画面でできること

- **volzz を有効にする** — オフにすると音量キーに一切介入しない
- **長押しと判定する時間** — 250〜1000 ミリ秒をスライダーで調整（初期値 450）。
  短くすると曲送りが速くなるが、少し長めの音量操作が誤って曲送りになりやすい
- **再生中だけ介入する**（初期値オン）— 音が鳴っていないときは音量キーを完全に
  素通しする。普段の音量操作に痕跡を残さないための既定値
- **曲送りのときに振動する**（初期値オン）— 次の曲は 1 回、前の曲は 2 回。
  画面を見なくても、送れたことと向きが分かる
- **上下を入れ替える** — 長押しの向きを逆にする
- **動作確認** — 受け取ったキーイベントの回数と、直近の動きを時刻つきで表示。
  端末側のバイブレーションが切られているときは、その警告も出す

## 横取りの仕組み

OS は「この押下がこれから長押しになるか」を**事前には教えてくれない**。
押した瞬間に音量を動かしてしまうと、長押しだったと分かった時点で戻すしかなく、
音量が 1 段上がってから下がる、という見苦しい動きになる。

そこで volzz は押下を完全に横取りし、**指が離れて「短押しだった」と確定してから**
音量を動かす。曲送りのときに音量が動くことは一度もない。

短押しの反応が遅れるのは「実際にボタンを押していた時間」のぶんだけで、
判定時間（初期値 450ms）まるごとではない。軽くタップすれば 100ms 前後で音量が動く。

押下を握り潰すこと自体も必須。通してしまうと以降の自動リピートは
システム側（`InputDispatcher`）が生成するようになり、そのリピートは
アクセシビリティのフィルタを通らない。つまり volzz からは見えず、握り潰せない。

### 画面が消えているとき

画面が消えているあいだ、音量キーは**アクセシビリティサービスには届かない**。
volzz 側の作りをどう直しても届かない。理由は AOSP の二段構えにある。

1. `PhoneWindowManager#interceptKeyBeforeQueueing()` は、画面が消えていて
   注入されたキーでもないなら `ACTION_PASS_TO_USER` を立てない（`result = 0`）。
2. `AccessibilityInputFilter#onInputEvent()` は `FLAG_PASS_TO_USER` の無い
   イベントをハンドラに回さず、そのまま素通しする。

つまり `onKeyEvent()` は一度も呼ばれない。そのかわりシステムは、行き場の
なくなった音量キーを `MediaSessionLegacyHelper#sendVolumeKeyEvent()` で
**メディアセッションに配る**。宛先は「再生中のセッションのうち、音量を自分で
扱えるもの」（`MediaSessionStack#getDefaultVolumeSession()`）。

そこで volzz は、**画面が消えている間だけ**、音量を自分で扱うと宣言した
セッション（`VolumeProvider`）を立てて受け皿にする。届き方はこうなる。

| 物理キー | 受け皿に届くもの |
|---|---|
| 押した | `onAdjustVolume(+1)` / `onAdjustVolume(-1)` |
| 離した | `onAdjustVolume(0)`（UP は direction 0 に変換されて届く） |

離した合図が来るので、画面が点いているときと同じ「離すまで音量を動かさない」を
そのまま守れる。**画面が消えていても、曲送りのときに音量は動かない。**

#### 短押しの音量は `adjustStreamVolume()` で動かす

受け皿を立てている間、**`adjustSuggestedStreamVolume()` は使えない。**
あれは `MediaSessionLegacyHelper#sendAdjustVolumeBy()` を通る、つまり
「いまの音量キーの宛先」に配られる仕組みで、その宛先は volzz 自身だからだ。
呼ぶと自分の `onAdjustVolume()` に戻ってくる。音量は動かないまま押下と数えられ、
離した合図も来ないので、450ms 後に長押しが成立して曲が送られる（v7 の不具合）。

`adjustStreamVolume()` は `AudioService` に直接行くので回らない。画面が
点いている間（受け皿を立てていない間）は `adjustSuggestedStreamVolume()` の
ままでよい。そちらはストリームの選び方も音量パネルの出し方も端末本来のものになる。

この「宛先が自分」は音量を動かす側からも見える。画面が消えている間に
`adb shell cmd media_session volume --stream 3 --set 6` を投げても端末の音量は
変わらない。volzz の受け皿に吸われるからだ。

#### 先頭を保ち続ける

音量キーの宛先は「再生中のセッションのうち、いちばん最近先頭に来たもの」。
**曲を送るとプレイヤーが先頭に戻ってくる。** 曲送りを受けたプレイヤーが
`STATE_SKIPPING_TO_NEXT` を報告すると、それは無条件で先頭に来る状態
（`MediaSessionRecord.ALWAYS_PRIORITY_STATES`）だからだ。放っておくと
**1 回曲を送ったあと、次の長押しから音量が動いてしまう**（v5 の不具合）。
曲が自然に次へ進んだときも同じことが起きる。

そこで volzz も `STATE_SKIPPING_TO_NEXT` を申告して先頭に押し戻し、すぐ
`STATE_PLAYING` に戻す。どちらも「再生中」の扱いなので、押し戻しの途中で
受け皿が外れることはない。押し戻すのは曲送りの直後（200 / 600 / 1200 ms）と、
画面が消えている間の 1.5 秒ごと（何も鳴っていないときは競争相手も居ないので休む）。

セッションには **`setCallback()` が必須**。`MediaSession#postToCallbackDelayed()` は
`mCallback` が `null` だとメッセージを捨てるので、コールバックを付けずに
`VolumeProvider` だけ渡すと、システムは音量キーをこのセッションに配るのに
`onAdjustVolume()` が一度も呼ばれない。**キーだけ握り潰して何も起きない**状態になる
（v4 の不具合）。`mCallback` は `setCallback()` でしか作られない。

曲送りは今までと同じ `dispatchMediaKeyEvent()` で送る。メディアボタンの宛先は
「直前に実際に音を出した uid のセッション」で決まるので（`AudioPlayerStateMonitor`）、
音を鳴らさない volzz が受け皿を持っていても、再生中のプレイヤーから宛先を
奪うことはない。ヘッドセットの再生／一時停止も今までどおりプレイヤーに行く。

画面が点いたら受け皿はすぐ片づけるので、点いている間の音量パネルの見え方は
変わらない。「再生中だけ介入する」がオンで何も鳴っていないときは何もしない
（画面が消えているときの端末本来の動きも、そこでは音量キーを捨てている）。

### 曲送りの手応え

画面が消えていると、曲が送れたかどうかは音が変わるまで分からない。曲の頭が
静かだと、押し方が足りなかったのかどうかも分からない。そこで送った直後に短く
振動する。**次の曲は 1 回（40ms）、前の曲は 2 回（25ms を 70ms 空けて）。**
ポケットの中でも向きが分かる。

分かるのは「メディアキーを**送れた**」ことまでで、プレイヤーが実際に曲を変えた
かどうかではない。`dispatchMediaKeyEvent()` は結果を返さず、プレイヤーの状態を
覗くには通知へのアクセス権が要る（volzz は取らない）。

**鳴らないときは、まず端末側の設定を疑う。** 端末全体のバイブレーションが切られて
いると（`Settings.System` の `vibrate_on = 0`、設定 → 音と振動）、アプリが何を頼んでも
`VibratorManagerService` が `ignored_for_settings` で捨てる。volzz に限らず着信も
アラームも鳴らなくなる設定なので、気づきにくい。volzz はこれを見て、動作確認の先頭に
「端末側のバイブレーションがオフです」と出す（v9）。`adb` で見るなら

```sh
adb shell dumpsys vibrator_manager | grep -i volzz
```

で、要求が届いているか、届いたうえで捨てられているかが分かる。

眠っている端末では `postDelayed` が時刻どおりに起きないことがあるので、
長押しの判定はタイマーだけに頼らず、**離した時刻から押していた時間を測り直して**
拾い直す。CPU が止まっても取りこぼさない。

### そこに至るまで

- **v1** — 短押しを端末任せにするため最初の押下をシステムに通した
  → 曲送りのあともキーを離すまで音量が上がり続けた（上のリピートの話）
- **v2** — 押下は横取りしつつ、その場で音量を動かし、長押し成立時に戻した
  → 音量が 1 段上がってすぐ下がってから曲送りされた
- **v3** — 離すまで音量を動かさない。**曲送り時に音量は一切動かない**
- **v4** — 画面が消えている間は曲送りが起きなかった。アクセシビリティでは
  原理的に届かないと分かったので、消えている間だけメディアセッションで受ける
  → `setCallback()` を呼んでおらず、キーを握り潰すだけで何も起きなかった
- **v5** — `setCallback()` を付けた。動作確認に「最近の動き」（直近 14 件、
  logcat にも同じ行）を足して、画面が消えている間の動きをあとから読めるようにした
  → 消灯中に効くのは 1 回だけで、2 回目からは音量が上がるだけになった。
  曲送りを受けたプレイヤーが先頭に戻り、受け皿が押し下げられていた
- **v6** — 受け皿を先頭に押し戻し続ける。**消灯中でも続けて曲を送れる**
- **v7** — 曲送りの手応えとして短く振動する。`VIBRATE` を足した（唯一の権限）
  → 消灯中の短押しで音量が動かず、代わりに曲が送られた。自分で動かした音量が
  自分の受け皿に戻ってきていた
- **v8** — 消灯中の音量は `adjustStreamVolume()` で動かす。**実機で数値を確認した**
  （下記）
- **v9** — 端末全体のバイブレーションが切られていると振動は鳴らない。原因がそこだと
  分かるよう、動作確認に警告を出す

## 実機で確かめたこと

v8 を Xperia XQ-FS44 / Android 16 (API 36) で確認した。画面を消したまま
物理ボタンを押し、`adb` で音量とログを読んだ結果。

| やったこと | 音量 | volzz のログ |
|---|---|---|
| 短押し ×3（間隔 316ms / 357ms） | 5 → **8**（3 段ちょうど） | 「短押し → 音量を上げた」×3 |
| 長押し ×3（連続） | 8 → **8**（動かない） | 「長押し → 前の曲へ」×3、毎回成立 |

短押しは 1 回につき 1 段だけ動き、余計な曲送りは起きない。長押しは続けて何回でも
効き、音量は 1 段も動かない。画面が点いている間の動きは今までどおり。

同じ手順で追試するなら、画面が消えている間の音量は
`adb shell cmd media_session volume --stream 3 --get` で読める（`--set` は
受け皿に吸われるので効かない）。`adb logcat -s volzz` で volzz の判断が並ぶ。

別の端末で使うときは、次を見ておくとよい。

1. **画面消灯中の長押しを続けて何回も** — 2 回目以降も曲が送られるか
2. **画面消灯中の短押し** — 音量が 1 段だけ動くか。曲送りが起きないか
3. **長押し** — 画面が点いている状態で、音量が一切動かずに曲が送られるか
4. **短押し** — 音量が動き、音量パネルが出るか。遅れが気になるか
5. **音量パネルの見え方** — 画面を消して点けたあと、音量キーを押したときに
   出るパネルが普段どおりか（受け皿を片づけ忘れていれば、ここに出る）

うまく動かないときは volzz の「動作確認」を見る。画面消灯中の分は
2 行目（**画面が消えている間に受け取った音量キー**）に数える。この数字が
増えていなければ、受け皿までキーが来ていない。増えているのに曲が送られない
なら、送った先（プレイヤー）が `MEDIA_NEXT` を拾っていない。

その下の「最近の動き」に直近 14 件が時刻つきで残る。画面が消えている間の動きも
ここで読める。同じ行は logcat にも出るので、USB が繋がっているなら

```sh
adb logcat -s volzz
```

で押しながら追える。端末側の事情を見るなら `adb shell dumpsys media_session`
（`volzz` のセッションが居るか、音量キーの宛先になっているか）。

### キーが届かないとき（他の端末で使う場合）

`accessibilityEventTypes` を指定していない（画面のイベントを一切受け取らない）
のが理由である可能性がある。その場合は
`app/src/main/java/com/volzz/VolzzService.java` の `onServiceConnected()` で

```java
info.eventTypes = 0;
```

を

```java
info.eventTypes = AccessibilityEvent.TYPE_WINDOW_STATE_CHANGED;
```

に変えて再ビルドすれば直る。privacy の観点では「前面のアプリ名が分かる」分だけ
情報が増えるので、必要になってから変える。

## ビルド

```sh
./gradlew assembleRelease
# → app/build/outputs/apk/release/app-release.apk を volzz.apk にコピーして配る
```

- JDK 17、Android SDK（platform 36 / build-tools 36.0.0）
- 依存ライブラリなし（AndroidX も使わない）。だから APK が 42 KB で済んでいる
- 署名鍵は `keystore/volzz.jks`（パスワードは `keystore.properties`、有効期間 30 年）。
  **この鍵は捨てないこと。** 失うと同じアプリとして更新できなくなり、
  入れ直しが必要になる

## 構成

```
app/src/main/
  java/com/volzz/
    VolzzService.java   画面が点いている間の横取りと長押し判定
    ScreenOffHook.java  画面が消えている間の受け皿（メディアセッション）
    Media.java          音量操作とメディアキー送出（上の二つで共有）
    MainActivity.java   設定画面と動作確認
    Prefs.java          設定の保存と診断情報
  res/xml/accessibility_service_config.xml   サービスの権限を最小に絞る宣言
  AndroidManifest.xml
```
